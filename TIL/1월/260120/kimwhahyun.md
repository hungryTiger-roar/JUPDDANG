> ### GIT 저장소의 이해
* **로컬 저장소 (Local):** : 내 컴퓨터의 개인 작업 공간
* **원격 저장소 (Remote):** : 팀이 공유하는 클라우드 서버 공간.
* **핵심 가치:** : 작업 이력 추적 (History), 코드 병합(Merge),안전한 백업 (Backup)

---

## 2. 실무 핵심 루틴 (Workflow)

1. **Sync** : `git pull` - 작업 전 최신 코드 확보.
2. **Add:** : `git add` - 수정 사항을 스테이징 영역에 추가
3. **Commit:** : `git commit -m` - 의미 있는 작업 단위 기록
4. **Push:** : `git push` - 원격 저장소에 업로드 및 공유

## 3. 필수 에티켓
* **1일 1커밋:** : 작업 단위는 작게, 자주 기록하기
* **충돌 관리:** : 충돌은 자연스로운 소통 과정임을 인지하고 팀원과 상의해서 해결
* **브랜치 정리** : Merge가 완료된 브랜치는 즉시 삭헤하여 혼란 방지

## 4. 우리팀의 깃 전략 숙지

> ### 커밋 규칙
- **일반 커밋** : [지라 티켓번호] feat : 회원 가입 API 연동
- **작업 중 기록** : [지라 티켓번호] feat : 로그인 UI 작업 #time 2h
- **이슈 닫기** : [지라 티켓번호] feat : 소셜 로그인 연동 완료 #time 4h #done

> ### 브랜치 컨벤션
- master(main) : 최종 배포용
- dev (2단계) : 개발 단계의 코드를 통합하는 공간 (작업 분기 시 기준접)
- feature/fix/refactor(3단계) : 작업용


- 브랜치 타입 
  - FEATURE : 새로운 기능 개발
  - FIX : 버그 수정
  - REFACTOR : 리팩토링
  - hotfix : 긴급 수정

- 지라 명령어
  - #time 1h 30 : 1시간 30분 작업 시간 기록 (w:주, d:일, m:분)
  - #dome : 티켓을 'done'으로 이동
  (작업이 끝났지만 검토가 필요한 경우)
  - #in-progress : 티켓 상태를 '진행 중'으로 이동
  - #commment : 내용 티켓에 댓글 등록
  - #close : 지라 티켓을 완전히 '닫음' 상태로 변경
