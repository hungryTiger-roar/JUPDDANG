## 1. API First Design과 개발 문서

### 왜 API가 중요한가?
- **정의:** 단순한 인터페이스를 넘어, 어플리케이션 간의 데이터와 기능을 교환하는 **개발자들의 약속**.
- **API First Design:** 코드 구현 이전에 API의 규격과 동작을 가장 먼저 설계하는 방식. 이는 UI/UX를 포함한 전체적인 설계를 미리 정리하는 과정을 의미함.

### 협업 방식: 동기식 vs 비동기식
| 구분 | **비동기식 (Asynchronous)** | **동기식 (Synchronous)** |
| :--- | :--- | :--- |
| **방식** | 미리 정의된 문서를 기준으로 각자 개발 | 배포된 API를 직접 호출하며 확인 및 개발 |
| **비유** | 모든 선수가 각자 시간에 맞춰 출발 | 앞 선수가 바통을 넘겨줘야 다음 선수 출발 |
| **장점** | 개발 준비 기간 단축, 병렬 작업 가능 | 즉각적인 동작 확인 및 피드백 가능 |
| **단점** | 기준이 명확하지 않으면 비용 소모 큼 | API 오류 시 전체 프로젝트 대기 발생 |
| **결론** | **상황에 따라 두 방식을 적절히 혼용하는 것이 최선.** |

### 필수 개발 문서 종류
각 문서는 독립적이지만 서로 긴밀하게 연관되어 있다.

1. **Wireframe:** FE의 전체 범위를 시각화 (팀원 간 검토용).
2. **기능명세서:** BE가 구현할 기능 목록, 요구/제한 사항 정리.
3. **API 연동 규격서:** FE-BE 간 인터페이스 규격 (정상/비정상 응답 포함).
4. **ERD (Entity Relationship Diagram):** 데이터를 Table 레벨까지 정리. 

[Image of Entity Relationship Diagram example]

5. **Sequence Diagram:** UI부터 DB까지의 상세 프로세스 흐름도. 
6. **Gantt Chart:** 누가, 언제, 무엇을 할지 정리한 일정표.

> **Insight:** "곤경에 빠지는 것은 무엇인가를 모르기 때문이 아니라, 무엇인가를 확실히 안다는 착각 때문이다." - *Mark Twain*

## 2. 개발자의 소프트 스킬: 커뮤니케이션

기술 업계의 '팩트 폭격' 문화 속에서 생산성을 높이는 대화법.

### 팩트(Fact)의 재정의
- 팩트는 때로 개인의 느낌이나 감(Feeling)일 수 있다.
- "너는 X를 이해 못 한 것 같아" (비난) vs "X는 ...이어야 해" (도움) → **내 판단을 덜어내고 도움 되는 부분만 말하기.**

### 건설적인 피드백 방법 (안 아프게 말하기)
1. **I-statement:** "네가 늦어서..."(X) → **"나는 전체 일정이 늦을까 봐 걱정돼"** (O)
2. **공통 목표 환기:** "우리 팀의 목표 달성을 위해 이렇게 하는 게 좋겠어."
3. **상대 입장 확인:** "이러한 상황이라 그렇게 한 것 같은데~" (공감 후 제안)

### 버려야 할 태도 (Toxic Traits)
- **사무적/기계적 말투:** 효율적일지 몰라도 팀 분위기를 해침.
- **습관적 비관:** 대안 없는 비판은 편견(Bias)일 뿐. **대안을 제시할 것.**
- **거들먹/빈정거림:** 상대의 노력을 무시하는 행위 금지.
- **수동적 공격성 (Passive Aggression):** 투명하게 소통하지 않고 돌려 말하거나 뒤에서 불만 표출 금지.

## 3. 프로젝트 개발 로그 (SNS 서비스)

### 📝 변경 사항 요약

#### 1. DB 컬럼명 변경 및 예약어 이슈 해결
- **문제:** `POST` 테이블의 `like` 컬럼이 SQL 예약어와 충돌.
- **해결:** 컬럼명을 `like_cnt`로 변경하여 충돌 방지 및 직관성 확보.
- **참고:** 이제 쿼리 작성 시 백틱(\`) 없이 사용 가능.

#### 2. 작성자 정보 표기 방식 고도화
- **기존:** 사용자 ID(`userId`)를 단순 문자열로 저장.
- **변경:** `Account` 엔티티와 `@ManyToOne` 연관관계를 맺어, 실제 닉네임(`nickname`)을 반환하도록 수정.

#### 3. 팀 협업을 위한 리팩토링
- **동기화:** 팀원(진우님) 코드와의 병합을 위해 메서드명 통일.
- **수정:** `Account` 엔티티 내 `getName` ➡️ `getNickName`으로 변경.
