# API-First Design

## API란?

- 애플리케이션 사이 데이터, 특징 및 기능을 통신으로 교환하는 매개체, 개발자들의 약속

---

## API 같은 규격 정리는 왜 하는 건가요?

- 실제 개발 이전 단계, 개발 할 내용을 정리하는 과정에서 상당수 UI/UX까지 함께 정리할 수 있기 때문

---

## API First Design이란?

- API 설계의 우선 순위를 첫번째로 가져가는 것
- 코드 구현 이전에 API의 규격과 동작을 가장 먼저 설계

---

## 장점

- 개발 효율성 개선
- 비용, 시간 절감
- 개발 경험 향상
- 보안 강화
- 협업 능력 증가

---

## 진행법

### 비동기식

- 상호작용 없이, 미리 정리한 규칙대로 실행
- **우선 정의하여 문서화 한 API**를 기준으로 FrontEnd에서 개발
- 예시
    - 모든 선수가 각자 시간에 맞춰 출발, 출발과 무관하게 도착 순서대로 처리
- 장점
    - 개발 이전 단계에서 팀원 간에 프로젝트에 대한 이해를 일치 시킬 수 있음
- 단점
    - 준비해야 할 기준이 명확하지 않을때, 프로젝트의 준비기간이 대폭 증가하여 비용 소모가 매우 커질 수 있음

### 동기식

- 상대의 반응을 확인하고 처리
- **실제 동작하는 API**를 기준으로 FrontEnd에서 개발
- 예시
    - 앞선 선수가 바통을 넘겨줘야지만 다음 선수가 출발 가능
- 장점
    - 개발된 API를 즉시 호출하여 확인하니 즉각적인 동작 및 오류 확인과 일부 기능 테스트 가능
- 단점
    - API에 오류가 있을 때 커뮤니케이션과 개발의 반복으로 프로젝트 전체의 비용소모가 매우 커짐

### 추천

- 상황에 따라 혼용하는 것이 좋음
- 시점에 따라 방법을 달리하는 것이 좋음

## 개발(설계) 문서

- 모든 개발 문서들은 각각의 역할이 다르며 개발 관계자들의 이해도를 맞추기 위해 작성
- 각각의 개발 문서들을 독립적이지만 서로 연관되어 있음

### Wireframe

- FE의 전체적인 개발 범위를 BE에서도 이해할 수 있도록 정리한 것
- 팀원들은 기능별로 요청 / 응답시 어떤 데이터를 전달해야 할지 미리 보기 하며 검토 가능

### 기능명세서

- Wireframe을 기반으로 BE에서 구현 해야 할 기능 목록을 요구사항, 제한 사항 함께 정리한 것
- FE는 기능명세서가, 개발에 문제가 없는지 확인
- BE는 해당 기능명세서를 분석하여, API 설계에 적용

### API 연동 규격서

- 기능명세서를 기반으로 BE와 FE 사이의 인터페이스로서 정상적, 비정상적 요청에 대한 처리 등 전체적인 규격을 정리한 것
- FE는 해당 연동규격서를 분석하여, Front 설계에 적용
- BE는 연동규격서를 작성하여 오류없고 신속한 로직 개발

### ERD

- API 명세서를 기반으로 BE와 주고 받을 데이터를 실제 Table 레벨까지 정리한 것
- FE는 Front 개발에 필요한 데이터가 DB에 모두 있는지 확인
- BE는 API 연동규격서의 내용이 DB에 모두 반영 되었는지 확인

### Sequence Diagram

- Wireframe 부터 ERD까지 설계한 개발 문서들을 대상으로 UI부터 API, 데이터와 DB Table까지 각 Process의 상세한 Flow를 정리한 것
- 기능별로 설계한 내용이 모두 반영되었는지, 추가 할 내용은 없는지 등 FE, BE 모두 Process를 종합 검토

### Gantt Chart

- 설계한 모든 내용들이 종합적으로 적용되어 ‘누가’, ‘언제’, ‘무엇을’ (누구와) 실행할지 정리한 것
