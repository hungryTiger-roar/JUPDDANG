## 1. AI 시대의 개발자 (Mindset)

### 10년 전과 현재의 데자뷰
- **과거:** "StackOverflow 복붙만 하는데 제가 개발자가 맞을까요?" (IDE 자동완성 의존 공포)
- **현재:** "GPT 복붙만 하는데 제가 개발자가 맞을까요?" (AI 의존 공포)
- **결론:** 이것은 단순한 매체의 발전일 뿐이다. 변화를 거부하지 말고, **생산성의 흐름(Flow)**에 올라타야 한다.

### AI 활용의 핵심: 통제권 (Control)
AI에게 주도권을 넘기지 말고, **내가 설계한 구조대로 AI가 타이핑하게** 만들어야 한다.

| 구분 | **초보적인 질문 (지양)** | **개발자의 질문 (지향)** |
| :--- | :--- | :--- |
| **방식** | "React 무한 스크롤 구현해줘." | "React Query와 Intersection Observer를 사용해서 구현해. 스크롤 위치는 SessionStorage에 저장해서 복원되게 하고, 메모이제이션으로 최적화해줘." |
| **의미** | 결과물만 요구 (의존) | **구조와 로직을 설계 후 코딩만 위임 (통제)** |

### 업무 방식의 변화: Chain Of Thought (CoT)
한 번에 모든 것을 시키지 말고, **사고의 사슬**을 연결하듯 단계별로 지시한다.

1. **분석:** "현재 코드베이스를 분석해서 기능이 들어갈 위치를 찾아."
2. **계획:** "좋아, A 기술을 써서 B 방식으로 구현 가능해?"
3. **실행:** "계획대로 코드를 작성해."
4. **복기:** 알파고 이후 바둑 기사들처럼, AI가 짠 코드를 리뷰하며 학습한다.

### 미래의 개발자
- **대체 가능성:** 단순 코더(Coder)는 대체되지만, 책임지는 사람(Developer)은 남는다.
- **조종사(Pilot):** 자동 운항(AI)이 가능해도, 위기 상황의 의사결정과 책임은 인간의 몫이다.
- **새로운 직무:**
  - **Problem Solver:** 백/프론트/데이터를 아우르는 문제 해결사.
  - **Product Engineer:** PM + SW Engineer의 융합.
- **방향성:** 평균적인 것은 대체된다. **독창적이고 뾰족해져야(Sharp) 한다.**

### 🎸 기타 특이사항 (Technical Notes)

#### 1. 랭킹 집계 방식 변경
- **Paging 적용:** 기존 상위 10명 조회 방식에서 대용량 데이터 대응을 위해 `Pageable`/`Slice` 방식으로 변경.
- **월간 집계:** JPQL의 `GROUP BY`와 `SUM`을 활용해 실시간으로 해당 월의 점수 합산.

#### 2. API 파라미터 안내
- **전체 랭킹:** `page` (기본 0), `size` (기본 10).
- **월간 랭킹:** `year`, `month` 파라미터 생략 시 서버 시간 기준 **'현재 연/월'**로 자동 설정.

#### 3. 티어(Tier) 자동화
- `PloggingLevel` Enum을 활용하여 점수(`score`)만 있으면 자동으로 **티어(Label)**와 **배지 이미지**가 매핑되도록 구현 (유지보수성 증대).
