## 🎯 커리어 전략: 대기업 vs 작은 회사

### 작은 회사 → 대기업 루트
```
작은 회사에서 경력/실력 쌓기
         ↓
경력직/중고신입으로 대기업 도전
```

#### ✅ 이 루트가 효과적인 조건

**제대로 배울 수 있는 환경이어야 함:**
- 배울 만한 사수가 있는가?
- 기술적으로 성장할 수 있는 환경인가?
- 코드 리뷰, 협업 프로세스가 있는가?

#### ⚠️ 주의사항
```
❌ 배울 게 없는 작은 회사
   → 시간 낭비, 경력 공백

✅ 성장 가능한 작은 회사
   → 실무 경험 + 기술 성장
   → 대기업 경력직 도전 가능
```

## 🌱 야생에서 성장하기

### 회사 밖에서 더 많이 배울 수도 있다
```
📚 오픈소스 기여
   - 실제 프로덕션 코드 경험
   - 글로벌 개발자들과 협업
   - 포트폴리오 강화

💻 사이드 프로젝트
   - 본인만의 서비스 구현
   - 기획부터 배포까지 전 과정 경험
   - 실전 문제 해결 능력

🚀 창업 도전
   - 비즈니스 감각 + 기술력
   - 주도적 경험
   - 실패해도 배우는 게 많음

🤝 현직자 네트워킹
   - 스터디, 밋업, 컨퍼런스
   - 실무 인사이트 획득
   - 커리어 기회 확대
```

**핵심:**
> 회사가 전부가 아니다. 
> 스스로 성장할 수 있는 환경을 만들어라.

## 🏢 기업 유형별 특징

### 전통적 기업 (대기업, 공기업)
```
특징:
✅ 원하는 인재상이 뚜렷
✅ 전사적 프로세스가 잘 정립
✅ 체계적인 교육/복지
✅ 안정적인 근무 환경

적합한 사람:
- 체계적인 환경을 선호
- 명확한 역할/책임을 원함
- 안정성 중시
```

### IT 서비스 기업 (스타트업, 중소IT)
```
특징:
✅ 인재상보단 기본기 중시
✅ 유연한 조직 문화
✅ 빠른 의사결정
✅ 다양한 경험 가능

적합한 사람:
- 빠른 성장을 원함
- 자율성을 선호
- 변화에 유연함
```

## 💡 자주 들었던 질문 (FAQ)

### Q1. 처음부터 큰 회사에 가야 할까요?

#### 큰 회사의 장점
```
💰 베이스 연봉
   - 신입 연봉이 높음
   - 복지 혜택 좋음

👥 좋은 사람들
   - 우수한 동료들 많을 확률 높음
   - 네트워크 형성 유리

📚 체계적 교육
   - 신입 교육 프로그램
   - 멘토링 시스템

🏷️ 경력 브랜딩
   - 이력서에서 유리
   - 이직 시 긍정적 평가
```

#### 고려사항
```
⚠️ 큰 회사 = 무조건 좋은 건 아님
   - 배치에 따라 천차만별
   - 레거시 시스템만 만질 수도
   - 성장 기회가 제한적일 수도

✅ 작은 회사에서도 성장 가능
   - 더 많은 재량과 책임
   - 빠른 의사결정
   - 다양한 경험
```

**결론:**
> 무조건 큰 회사가 아니라, 
> **성장할 수 있는 환경**이 중요하다.

### Q2. 제가 원하는 직무가 아닌데 가야 할까요?

#### 직무 미스매치의 문제
```
시간이 지날수록 전환이 어려워진다:

신입 (0-1년)
   ↓ 전환 쉬움
주니어 (1-3년)
   ↓ 전환 가능
미들 (3-5년)
   ↓ 전환 어려움
시니어 (5년+)
   ↓ 전환 매우 어려움
```

#### 왜 전환이 어려워지는가?

**1. 매몰 비용**
```
3년 동안 A 직무 경험
   → A 직무로 이직하면 연봉 상승
   → B 직무로 전환하면 신입 대우

심리적 부담:
"3년을 버린다고?"
```

**2. 연차에 대한 기대치**
```
3년차 개발자에게 기대하는 것:
- 독립적 업무 수행
- 주니어 멘토링
- 설계 능력

신입 직무로 전환:
- 기대치 충족 못함
- 나이/연차 vs 실력 괴리
```

#### 직무 전환 타이밍
```
📊 체감 난이도:

신입 (0-1년): ⭐ (쉬움)
   - 아직 특정 직무에 깊게 투입 안 됨
   - 신입 수준 기대
   - 전환 부담 적음

주니어 (1-3년): ⭐⭐⭐ (보통)
   - 전환 가능한 마지노선
   - 기본기 증명 필요
   - 연봉 하락 감수

미들+ (3년+): ⭐⭐⭐⭐⭐ (어려움)
   - 매몰 비용 큼
   - 나이/연차 부담
   - 경력 단절로 보일 수 있음
```

#### 의사결정 프레임워크
```
상황 1: 안정적으로 직무 전환 가능할 것 같다
   예) 사내 직무 전환 제도
       팀 이동 기회
       교육 지원
   
   → ✅ 간다
   → 일단 들어가서 전환 준비

상황 2: 도저히 직무 전환을 못할 것 같다
   예) 경직된 조직
       전환 사례 전무
       업무 강도 높아 학습 불가
   
   → ❌ 안 간다
   → 원하는 직무로 재도전
```

## 🎓 실전 조언

### 신입 공채의 함정
```
대기업 신입 공채:
   ✅ 입사는 쉬울 수 있음
   ❌ 직무 선택권이 없음
   ❌ 원치 않는 부서 배치 가능

문제:
"백엔드 하고 싶은데 
 임베디드 부서 배치"

해결책:
1. 직무 전환 가능성 확인
2. 안 되면 빨리 이직 준비
3. 3년 넘기지 말 것
```

### 직무 전환 시기
```
✅ 전환하기 좋은 시기:
   - 1-3년차 (체감상 베스트)
   - 기본기 쌓은 상태
   - 아직 매몰 비용 적음

⚠️ 전환하기 어려운 시기:
   - 3년차 이후
   - 특정 직무 전문가로 인식
   - 나이/연봉 부담
```

### 현실적 조언
```
이상적:
   원하는 회사 + 원하는 직무

현실:
   둘 다 안 되는 경우도 많음

우선순위:
   1순위: 직무 > 회사
   2순위: 성장 환경 > 브랜드
   3순위: 전환 가능성 > 현재 조건
```

## 📝 의사결정 체크리스트

### 입사 전 확인사항
```
□ 이 회사에서 무엇을 배울 수 있는가?
□ 성장할 수 있는 환경인가?
□ 좋은 사수/동료가 있는가?
□ 원하는 직무인가?
□ 직무 전환이 가능한가?
□ 3년 후 어떤 개발자가 될 수 있는가?
```

### 직무 불일치 시 판단 기준
```
✅ 가도 되는 경우:
   □ 사내 전환 제도 명확
   □ 전환 성공 사례 多
   □ 1-2년 내 전환 가능
   □ 학습 시간 확보 가능
   □ 관련 프로젝트 참여 기회

❌ 가지 말아야 하는 경우:
   □ 전환 불가능한 조직
   □ 업무 강도 과도
   □ 성장 기회 없음
   □ 매몰될 것 같은 느낌
   □ 직관적으로 안 좋음
```

## 🎯 핵심 요약

### 1. 회사 크기보다 중요한 것
```
❌ 대기업 무조건 좋다
✅ 성장할 수 있는 환경이 좋다

조건:
- 배울 만한 사수
- 좋은 기술 스택
- 협업 문화
- 적절한 업무 강도
```

### 2. 직무는 최대한 맞춰서 시작
```
신입 → 주니어: 전환 쉬움 ⭐
주니어 → 미들: 전환 보통 ⭐⭐⭐
미들 → 시니어: 전환 어려움 ⭐⭐⭐⭐⭐

체감 마지노선: 3년차
```

### 3. 회사 밖에서도 성장하라
```
오픈소스 기여
사이드 프로젝트
네트워킹
창업 도전

→ 경쟁력 강화
→ 커리어 옵션 확대
```

### 4. 의사결정 원칙
```
직무 전환 가능? → ✅ GO
직무 전환 불가? → ❌ STOP

타이밍이 중요:
   빠를수록 좋다
   3년 넘기지 마라
```

## 💭 마무리

**당신의 커리어는 당신이 결정한다.**
```
✓ 회사가 전부가 아니다
✓ 직무가 회사보다 중요하다
✓ 성장 환경이 브랜드보다 중요하다
✓ 시기를 놓치지 마라 (3년 이내)
✓ 스스로 성장할 방법을 찾아라
```

**최악의 선택:**
> "원치 않는 직무에서 5년을 버티는 것"

**최선의 선택:**
> "성장할 수 있는 환경에서 
> 원하는 직무로 일하는 것"
