## 성장

### 1. 신입 개발자에게 기대하는 '성장 가능성'
면접관이나 회사가 신입에게 기대하는 것은 완성된 기술력이 아니다.
> "지금 당장 특정 지식의 부재가, 이 사람의 능력 부족을 의미하지 않는다."

**성장 가능성을 증명하는 방법:**
- **Deep Dive 경험:** 과거에 무언가를 깊게 파고들어 성장했던 경험을 제시해야 한다.
- **도전적 과제:** "과거 프로젝트에서 겪었던 가장 큰 난관은 무엇인가?"라는 질문은, 당신이 어떻게 문제를 해결하고 그 과정에서 무엇을 배웠는지를 묻는 것이다.

---

### 2. 성장의 정의 (Definition)
성장은 미래의 신기술을 미리 배우는 **'선행학습'이 아니라, 과거에 대한 '회고'다.**

- 최첨단 기술을 얼마나 많이 아느냐가 중요한 것이 아니다.
- **어제의 나, 일주일 전의 나, 한 달 전의 나보다 얼마나 나아졌는가?**
- 비교 대상이 '과거의 나'이고, 조금이라도 나아졌다면 성장하고 있는 것이다.

---

### 3. 성장을 가로막는 불안과 강박 다루기

**Q. 회사 기술 스택이 너무 구식이라 퇴근하고 새 프레임워크를 공부하는데 시간이 부족해요.**
- **A.** 아무도 당신이 뒤처졌다고 생각하지 않는다. 조급해하지 않아도 된다.

**Q. 5년 차인데 아는 게 너무 없어요.**
- **A.** 10년 차도 똑같은 고민을 한다. 영원히 하게 될 고민이니 받아들이자.

**Q. 내 주특기(예: 머신러닝)만 하고 싶은데 잡다한 일을 다 시켜요.**
- **A.** 회사의 과업을 해결하는 과정 자체가 성장이다. 당장은 무관해 보여도, 훗날 어떤 방식으로든 내 커리어에 도움이 된다.

---

### 4. 성장의 전략: 강점과 약점
- **과락(F) 없는 강점(A) 만들기:**
  - 모든 것을 다 잘할 필요는 없다.
  - 내 발목을 잡는 치명적인 약점(과락)만 없애고, 나만의 뚜렷한 강점을 벼리는 방향으로 나아가자.
- **지금 주어진 태스크에 몰입하기:** 막연한 미래보다 현재의 문제 해결이 성장의 가장 빠른 길이다.

---

### 5. 필연적으로 따라오는 불안 (Imposter Syndrome)
성장할수록 우리는 필연적으로 불안해진다.

- **가면 증후군 (Imposter Syndrome):** 나의 성취가 운 때문이고, 실력이 들통날까 봐 두려워하는 심리.
- **평범해짐의 역설:** 성장할수록 나보다 뛰어나거나 비슷한 사람들 틈으로 들어가게 되므로, 상대적으로 평범해 보인다.
- **무능해짐의 역설:** 자신의 능력 한계치까지 승진하거나 나아가기 때문에, 결국 자신의 무능함을 마주하게 된다.

### 6. 마인드셋
- **인적 자본 축적:** 짜치고 찌질해 보이는 일을 하는 것도 성장의 통과 의례다.
- **한계 효용 체감:** 성과에 대한 기쁨은 갈수록 줄어든다. 그러니 너무 조급해하지 말자.

## 댓글 기능 변경 사항 요약

**1. 댓글 기능 UX/UI 리팩토링 (S14P11D208-274)**

* **작성 UX 개선:** 댓글 작성 시 바텀시트가 닫히지 않도록 변경 및 작성된 댓글이 리스트 최상단에 즉시 반영되도록 수정 (Optimistic Update).
* **정렬 및 디자인:** 댓글 리스트 최신순(내림차순) 정렬 적용, 프로필 사진 크기 최적화 및 닉네임/본문 텍스트 색상 가독성 개선.

**2. 게시글 삭제 및 관리 기능 고도화 (S14P11D208-269)**

* **\[BE\] DTO 수정:** `PostResponseDto`에 작성자 `userId` 필드를 추가하여 프론트엔드 권한 확인 로직 지원.
* **\[FE\] 본인 확인 로직 수정:** 서버 데이터(Int/String)와 로컬 데이터 간의 타입 불일치로 인한 `isMine` 판별 오류 해결 (String 변환 비교 적용).
* **기능 구현:**
  * DB에 저장된 게시글 삭제 API(`DELETE`) 연동.
  * 로컬 임시 저장 글 삭제 및 **'이어쓰기'** 기능(작성 화면으로 데이터 복원) 구현.
* **UI 통일:** 임시 저장 글과 서버 게시글의 메뉴 버튼을 '삼선 메뉴(PopupMenu)'로 통일하고 위치 정렬 수정.

## 랭킹 페이지 변경 사항 요약

**1. 랭킹 조회 API 연동 (누적/월간)**

* **RankingService:** 누적(`getTotalRanking`) 및 월간(`getMonthlyRanking`) 랭킹 조회 메서드 구현
  * `Authorization` Header에 JWT 토큰 추가하여 401 에러 해결
  * API 엔드포인트 수정 및 `userId` 쿼리 파라미터 연동
* **RankingModel:** 백엔드 응답 구조(`topRankers`, `myRankWindow`)에 맞춰 데이터 파싱 로직 수정

**2. 랭킹 페이지 UI 리팩토링**

* **내 순위 강조(Highlight):** 리스트 내 본인 아이템에 테두리/색상 강조 적용으로 가시성 확보
* **레이아웃 최적화:**
  * 하단 고정 'MY RANK' 바 제거 (리스트 아이템과 중복되어 삭제 및 화면 공간 확보)

  * `ListView` 하단 Padding 추가하여 스크롤 시 마지막 아이템 잘림 현상 해결
* **데이터 바인딩:** 1\~3등(Podium)과 내 주변 랭킹 리스트(List) 분리 렌더링 적용

**3. 테스트 환경 구축 (DB & Redis)**

* 랭킹 데이터 검증을 위해 PostgreSQL(`account`, `ploggings` 테이블)에 더미 데이터 삽입
* 배포 서버 Redis 캐시 갱신을 위해 Swagger를 통한 플로깅 데이터 강제 주입 및 동기화 테스트 수행
