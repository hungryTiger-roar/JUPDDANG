## 📅 2026. 02. 02

### GPS 데이터 신뢰성 확보: Jitter 보정 및 구조 개선

위치 기반 서비스 개발 중 발생하는 GPS 튀는 현상(Jitter)의 원인을 파악하고, 이를 해결하기 위한 필터링 로직 적용 및 코드 리팩토링 방안을 수립했습니다.

#### 📌 Raw Data의 불확실성과 필터링(Filtering)의 필요성

* **문제 상황 (Issue)**
* 도심의 빌딩 숲 등에서 신호 반사(Multipath)나 위성 가시성 부족으로 인해 좌표가 순간적으로 튀거나 흐르는(Drift) 현상 발생.
* `map_screen.dart` 파일 하나에 UI 로직과 좌표 보정 로직이 혼재되어 코드 복잡도 증가.


* **원인 분석 (Cause)**
* **데이터의 본질:** 하드웨어(GNSS Chip)가 제공하는 Raw 데이터는 "정답"이 아닌 **"최선의 추측값"**이며, 본질적으로 노이즈를 포함함.
* **Accuracy의 역할:** Accuracy(정확도)는 단순한 참고용 숫자가 아니라, 현재 수신된 위치의 **'신뢰도(Weight)'**를 결정하는 핵심 메타데이터임. (GNSS 칩이 위성 배치(DOP)와 신호 강도(SNR)를 계산하여 산출).


* **해결 전략 (Solution)**
* **가중치 기반 필터링 (Kalman Filter 원리):** Accuracy를 기준으로 측정값(GPS)과 예측값의 반영 비율 조절.
* Accuracy 좋음 (예: 3m) → 측정값 신뢰 (반영비율 ↑)
* Accuracy 나쁨 (예: 50m) → 기존 예측값 유지 (반영비율 ↓)


* **책임 분리 (Refactoring):** `GpsFilter` 클래스 도입.
* 스트림으로 들어오는 데이터의 **'정수기(Filter)'** 역할 수행.
* 유효하지 않은 데이터(Accuracy > 30m 등)는 `null` 처리하여 UI 계층(`map_screen.dart`)에 도달하기 전 차단.





> **💡 오늘의 교훈**
> **"하드웨어는 데이터를 주고, 소프트웨어는 진실을 찾는다."**
> 센서가 던져주는 **Raw Data(날것)**를 맹신하는 것은 위험하다. **Accuracy(정확도)**라는 메타데이터를 **'거름망'**으로 사용하여, **유효한 신호**만을 걸러내는 필터링 로직이야말로 안정적인 위치 서비스의 핵심이다. **"입력을 의심하고 검증하라."**
