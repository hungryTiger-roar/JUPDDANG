1. 애자일 소프트웨어 (Agile Software)

오늘은 애자일 소프트웨어 개발 방식에 대해 정리했다.
애자일은 완벽한 계획을 먼저 세우는 방식이 아니라, 작은 단위로 빠르게 만들고, 피드백을 통해 지속적으로 개선하는 개발 방법론이다.

요구사항은 고정된 것이 아니라 변화 가능

짧은 주기의 반복(Sprint)을 통해 기능을 점진적으로 완성

문서보다 작동하는 소프트웨어, 개인보다 협업과 소통을 중시

👉 느낀 점
처음부터 모든 걸 완벽하게 하려는 부담을 내려놓고,
지금 할 수 있는 최선의 한 단계를 빠르게 만드는 게 더 중요하다는 걸 이해하게 됐다.

2. 기술 스택 (Tech Stack)

기술 스택은 하나의 서비스를 만들기 위해 사용하는 기술들의 조합이다.
단순히 “유행하는 기술”이 아니라, 문제 해결에 적합한 선택이 중요하다.

예시:

프론트엔드: Flutter, React, Vue

백엔드: Spring Boot, Node.js

DB: MySQL, PostgreSQL, Redis

인프라: Docker, CI/CD, Cloud

👉 느낀 점
기술 스택 선택은 실력 자랑이 아니라
팀 상황, 유지보수, 확장성까지 고려한 의사결정이라는 걸 깨달았다.

3. Make Real

“Make Real”은 아이디어를 머릿속에만 두지 말고 실제 결과물로 만들어보라는 개념이다.

완벽하지 않아도 된다

작동하는 최소한의 형태(MVP)면 충분

만들어봐야 문제도, 개선점도 보인다

👉 느낀 점
계속 고민만 하는 것보다,
조금 어설퍼도 구현해보는 행동력이 성장의 핵심이라는 생각이 들었다.

4. Copilot

Copilot은 개발자의 코드를 대신 생각해주는 존재가 아니라,
생각을 가속해주는 도구라는 점을 배웠다.

반복 코드, 기본 구조 생성에 강점

결국 판단과 책임은 개발자 몫

이해 없이 쓰면 실력이 늘지 않음

👉 느낀 점
Copilot을 “정답 생성기”가 아니라
학습 파트너로 활용해야 한다는 기준이 생겼다.

5. Antigravity

Antigravity는 기존의 개발 방식이나 고정관념에서 벗어나
다르게 생각하고 시도해보는 태도를 의미한다고 이해했다.

“원래 이렇게 해”라는 말 의심하기

불필요한 복잡함 줄이기

목적 중심으로 사고하기

👉 느낀 점
기술보다 중요한 건 사고방식이고,
틀을 깨려는 시도가 결국 더 나은 선택으로 이어진다는 걸 느꼈다.

✨ 오늘의 한 줄 정리

성장은 더 많이 아는 것이 아니라,
작게 만들고, 빠르게 시도하며, 계속 개선하는 과정에서 온다.
