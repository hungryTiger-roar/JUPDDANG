## 1. Backend: 왜 Python이 아니라 Spring인가?

### 📌 Python vs Java의 동시성 차이

* **Python (AsyncIO):**
* **작동 방식:** 단일 스레드(Single Thread) 기반의 이벤트 루프. I/O 작업(DB 대기 등) 시 문맥을 전환하여 효율을 냄.
* **한계 (GIL):** Global Interpreter Lock으로 인해 한 순간에 하나의 CPU 코어만 사용 가능. 복잡한 연산(CPU Bound) 발생 시 전체 서버가 멈출(Blocking) 위험이 있음.

* **Spring (Multi-Thread):**
* **작동 방식:** 요청마다 스레드를 할당하는 전통적인 멀티 스레딩 모델.
* **장점:** OS 레벨의 스레드를 사용하여 CPU 코어를 병렬로 활용 가능. 특정 요청이 무거워도 다른 요청에 영향을 덜 줌.


### 📌 팀 프로젝트 관점

1. **아키텍처 강제성:** Controller-Service-Repository 계층 구조가 명확하여, 팀원 간 코드 스타일 파편화를 방지.
2. **컴파일 타임 안정성:** 정적 타입 언어(Java)를 통해 런타임 에러를 사전에 차단.
3. **트랜잭션 관리:** `@Transactional`을 통한 데이터 무결성 보장이 강력함.

## 2. Frontend: Vue vs React

둘 다 Node.js 기반 빌드 환경을 사용하고 Virtual DOM을 통해 렌더링을 최적화한다는 점은 같지만, **상태 변화 감지 방법법**이 다르다.

### 📌 React의 불변성 vs Vue의 반응성

| 구분 | React (리액트) | Vue (뷰) |
| --- | --- | --- |
| **철학** | **불변성 (Immutability)** | **가변성 (Mutability) & 감지** |
| **감지 방식** | **Pull (전체 비교):** 데이터가 새 객체로 교체되면, 전체를 훑어서(Diffing) 변경점 찾음. | **Push (알림):** 데이터에 센서(Proxy)를 달아, 변경 시 구독자에게 알림을 줌. |
| **업데이트** | Top-Down 방식 (부모 → 자식) | Fine-Grained 방식 (정밀 타격) |
| **특징** | `setState`로 객체를 **교체**해야 함. | `state.value = 1` 처럼 **수정**하면 됨. |

### 📌 왜 React를 선택했는가?

1. **초기 렌더링 비용 절감:** Vue처럼 모든 데이터에 `Proxy(감시 센서)`를 부착하는 초기 비용이 없음. 대규모 데이터 처리에 유리.
2. **예측 가능한 데이터 흐름:** 단방향 데이터 흐름(One-way flow)과 불변성 덕분에, 앱이 복잡해져도 데이터의 상태 추적이 용이함.
3. **생태계와 커리어:** Spring 백엔드와 함께 엔터프라이즈 환경에서 가장 많이 쓰이는 표준 스택. JS/TS 자체 역량을 기르기에 적합.

## 3. 핵심 요약

* **Node.js의 역할:** 프론트엔드에서의 Node.js는 서버가 아니라, Java의 **JVM/JDK**와 같은 **'빌드 및 실행 환경'**이다. 결과물은 브라우저(JS)에서 돌아간다.
* **Virtual DOM의 본질:** 화면을 통째로 새로 그리는 것이 아니라, 메모리상에서 비교 연산을 빠르게 수행하여 **'실제 DOM 조작을 최소화'**하기 위한 기술이다.
* **기술 선택의 기준:** 단순히 "빠르다/쉽다"가 아니라, **"협업 시 휴먼 에러를 줄여주는가?", "유지보수가 용이한 구조인가?"**가 팀 프로젝트 기술 선정의 제1원칙이다.
