  ```

  BUG : 버그 발견

  DOCS : 문서 수정

 ***SUBJECT***

 제목은 50자가 넘지 않도록 하고, 마침표 특수 기호는 사용하지 않음
 영문은 동사 원형을 가장 앞에두고 첫 글자는 대문자 표기 (과거 시제 사용 하지 않음)
 제목은 개조식 (간결하고 요점적인 서술)
 EX) FIX, ADD

 ***BODY***

 어떻게 변경했는지보다 무엇을 변경했는지, 왜 변경했는지 설명

***FOOTER***

꼬리말은 OPTIONAL이고, 이슈 트레커 ID를 작성한다
여러개의 이슈번호를 적을 때는 쉼표(,)로 구분한다
이슈 트래커 유형은 다음 중 하나를 사용한다.
- FIX: 이슈 수정중
- RESOLVES : 이슈 해결시 사용
- REF : 참고할만한 이슈가 있을 때 사용
- RELATED TO : 해당 커밋에 관련된 이슈번호
EX) FIX: #45 , RELATED TO : #34, #23

-하나의 커밋에는 한 가지 문제만 적는다.

> ### 기술 용어

- MCP (MODEL CONTEXT PROTOCOL)
    - 기존 AGENT FRAMEWORK제공자와 TOOL제공자가 각각 INTEGRATION하지 않도록함
    - 둘이 서로 SDK 스펙 맞출 필요 없이 표준화된 프로토콜 사용
    - JSON-RPC/HTTP를 이용하는 LLM 애플리케이션과 TOOL 서버가 어떻게 통신하는지 정의한 규약

    - MCP 프로토콜 동작 원리
        - LLM APPLICATION이 TOOL 서버에 어떤 일을 할 수 있는지 툴 목록 요청
        - LLM APPKICAITON은 이 TOOL이 어떤 기능 제공할 수 있는지 이해가능
        - 이제 추가적인 정보가 필요시 LLM APPLICATION내의 AGENT가 판단하여 특정 TOOL호출하여 원하는 정보를 받음

    - 개발자에게 PROTOCOL 개발이란?
        - 서버와 클라이언트의 SDK를 제공한다.
        - 서버 SDK는 KOTLIN, PYTHON, TYPESCRIP를 위한 여러 프레임웍이 있다.

    - 중요한 3요소
        - 호스트 : AI모델이 돌아가는 애플리케이션 (클로드, GPT)
        - 클라이언트 : 호스트 안에 내장된 MCP와 통신하는 클라이언트
            - AI요청을 표준형식으로 변환함, 반대로 외부 응답을 모델이 이해할 수 있는 형태로 변환함
        - MCP 서버 : 원래 서비스의 기능이나 데이터를 제한된 형태로 공개함, 모델의 요청에 따라 특정 조회나 결나 수행 결과를 내보냄
                     정확히 AI가 필요한 컨텍스트만 얻도록 도움
            - EX) 피그마    
    - 흐름
        1) 디자이너가 커서 AI에게 피그마 디자인 파일을 붙여 넣으며 디자인 참고 컨텍스트 지정
        2) 자연어 지시 " 이 피그마에 있는 로그인 페이지를 리액트 코드로 만들어줘"
        3) 모델의 요청 처리로 커서의 내부 AI가 사용자 명령 이해 후 피그마 디자인의 세부 레이어 정보 필요하다고 판단함. 모델 자신의 MCP 클라이언트를 통해 FIGMA MCP 서버에 필요한 데이터 달라고 TOOL호출함
        4) 피그마 MCP 서버측 데이터 전달로 MCP서버는 요청을 받아 FIGMA API를 호출함으로써 실제 디자인 데이터 얻어옴. AI모델에 꼭 필요한 핵심 정보만 추려 알맞은 형태 EX) JSON형태로 커서AI에게 전달
        5) AI 응답 생성으로 커서AI가 사용자 명령에 대한 결과물을 만들어냄
        6) 결과 제공 및 피드백

    - 장점 
        - 사용자는 그냥 자연어로 명령했지만, 뒤에어 알아서 AI모델이 MCP호출하여 FIGMA API부터 데이터를 만드는 흐름 자동 전개됨
        - MCP서버는 FIGMA API로부터 얻은 방대한 정보 속 레이아웃과 스타일의 핵심만 추려서 모델에 전달하며 AI응답 정확성을 높임
        - 한 번 구현해두면 그 MCP 서버가 제공하는 여러 툴을 AI가 스스로 발견하며 사용가능해서 새로운 API를 학습시킬 필요 줄어든다.
        - API와 달리 단발성이 아닌 실시간 대화를 주고받는 양발성이다.


- AGENT
    - 기존 LLM은 기본적으로 학습 당시 습득된 지식만 사용하면서 학습되지 않은 정보에 대한 답변 생성 불가 및 파일검색, 음악 틀기 등등 불가능했었음
    - 이 LLM 어플리케이션 기능을 확장하기 위해 LLM이 다른 애플리케이션이나 데이터 소스와 상호 작용하도록함
    - LLM은 주어진 문제에 대해 어떤 TOOL을 사용했는지 생각하고 의사 결정을 해야하는데, 이 툴에서 얻은 정보를 통해서 답변을 만들어내는 역할하는 것이 AGENT임


- API
    - APLICAION PROGRAMMING INTERFACE의 약자로 어떤 서비스를 프로그래밍적으로 이용하기 위해 제공되는 기능 명세서
    - EX) 피그마 API는 HTTP요청으로 "이 파일의 프레임 목록을 달라" 또는 "이 텍스트 레이어의 내용을 수정해달라"라고 보낼 수 있는 정해진 규칙과 엔드포인트의 모음
    - 요청 - 응답의 단발성 상호 작용


> ### 기술 스택

- 리액트 
    - 사용자 인터페이스를 만들기 위한 JavaScript언어 기반 라이브러리
        - 자바스크립트 : 웹 분야에서 호면 개발하는 FB개발 언어로 정적인 웹 문서에 동작 부여할 수 있는 언어임
        - 라이브러리 : 특정 언어로 만든 프로그램이나 기능을 모아둔 집합의 정도

        - 장점
            - 가장 인기 있고, 채용 공고도 많다.

        - 특징
            - 컴포넌트 (재사용 가능한 각각의 독립된 모듈) 기반 구조
            - 컴포넌트 예시 - 헤더,메인, 푸터, 카드

            - 어떤 데이터가 변할 때마다 변화를 주는 것이 아니라 기존에 있던 뷰를 날리고 새롭게 리렌더링
            
        - 초기렌더링 
            - 중첩된 컴포넌트도 재귀적으로 랜더링되며 최상위 컴포넌트 랜더링 끝나면 render함수가 반환하는 객체 정보 사용하여 html코드 만들고, 우리가 정의한 실제 페이지의 DOM 요소 안에 주입시킴
        - 리렌더링
            - 컴포넌트에서 데이터가 변경될때 변경된 요소만 갈아끼운다.
            - 데이터가 바뀌면 컴포넌트는 render 함수를 재차 호출해서 뷰를 생성한다.
            - 렌더함수가 반환하는 결과는 바로 dom에 반영되지 않고 이전에 생성한 컴포넌트 정보와 다시 렌더링한 컴포넌트 정보 비교 후
              둘의 차이를 알아내 최소한의 연산으로 dom트리에 업데이트한다.

        - DOM
            - Document Object Model로 문서의 구조화된 표현을 트리형태로 제공하며 웹페이지를 스크립트 또는 프로그래밍 언어들에서 사용될 수 있도록 연결시켜주는 역할

        - 웹브라우저
            - DOM을 사용하여 HTML로 작성된 문서 객체에 자바스크립트와 CSS를 적용하여 보기 좋고, 동적으로 만들어줌
            - HTML문서 수신시 이를 변환해 노드들로 이루어진 DOM Tree만듦

- 도커
    - 컨테이너형 가상화 기술을 구현하기 위한 상주 애플리케이션 (dockerd라는 데몬)과 이 애플리케이션을 조작하기 위한 명령 도구로 구성된 프로덕트
    - 사용 예시)
        - 로컬에 아파치나 엔진엑스와 같은 웹서버 구축
        - 로컬에 도커만 설치시 몇 줄짜리 구성 파일과 명령어 한 줄로 애플리케이션이나 미들웨어가 이미 갖춰진 테스트용 가상환경 (도커 컨테이너)빠르게 구축가능
    - 장점
        - 개발환경 구축 및 개발 후 운영 환경에 대한 배포나 애플리케이션 플랫폼으로 가능함

- JENKINS
    - 지속적으로 통합 서비스를 제공하는 툴 (Continuous Integration)
    - 다수 개발자들이 하나의 프로그램을 개발하면서 버전 충돌을 방지하기 위해 각자 작업한 내용을 공유 영역에 있는 저장소에 빈번히 업로드함으로써 지속적 통합 가능하도록 해줌
    - 이전에는 당일 작성한 소스의 커밋이 완료된 심야 시간에 빌드했으나, 젠킨스는 깃과 같은 버전 관리 시스템과 연동시 자동적으로 자동화 테스트가 포함된 빌드가 작동되도록 설정 가능

    - 장점
        - 개인이 미처 실시하지 못한 코드 표준 준수 여부 검사 및 정적 분석을 통한 코드 품질 검사도 빌드 내부적으로 수행함
